Anatomy07 / 29

Agents as peers: mesh, seeds and gossip

Peer

A running agent service that advertises what it can do.

Mesh

All the peers that know about each other. No central list.

Seed node

A known address a new peer contacts to join. An entry point, not a leader.

Gossip (SWIM)

Peers ping each other and share news, so everyone converges on who's alive.

Membership, failure detection and capability announcements ride on gossip. Agent-to-agent messages go peer to peer.

Anatomy08 / 29

Why gossip, and what it costs

What you get

  • No registry or broker to run, scale or fail
  • Failure detection built in: silent peers go suspect, then dead
  • Capabilities announced: the roster writes itself, no redeploy
  • No permanent coordinator: any eligible peer can claim work
  • The same code from one process to a fleet

What it asks of your platform

  • Stable identity per node: a seed needs a stable name
  • TCP and UDP open on the mesh ports
  • Membership is eventually consistent, not instant
  • Work and state still live in Redis: gossip is not the source of truth

If you've run Consul or Cassandra, you've relied on the same idea. The right-hand column is why the platform choice comes next.

Memory: four tiers, one interface

Working

Scratchpad for the current step, discarded when it finishes.

Lives in: blob storageLifetime: the step

Episodic

An append-only ledger of what happened, in order. The audit trail.

Lives in: a Redis streamLifetime: 7 days by default

Long-term

The model compresses a long ledger into a summary, backed up to blob storage.

Lives in: Redis + blobLifetime: the workflow

Cross-session

Semantically searchable memory that spans workflows and restarts, not just the current one. A restarted agent recovers what it learned, not just its last checkpoint.

Lives in: an external memory serviceLifetime: across sessions

One object, UnifiedMemory, fronts all four tiers. For this tier, we use Athena, our open-source memory framework — it ships with three tiers of its own (short-term, mid-term, long-term graph). Set ATHENA_URL and every agent upgrades, with no code changes.

Tool access: one door, built in

Nexus: one call for OAuth2, API keys and Basic auth, with automatic token refresh

About 150 integrations ship as atoms: typed single-file functions the agent finds in a registry

Destructive tools declare an approval policy; execution is at-least-once, so keep tools idempotent

In JarvisCore, agents never hold a token. Nexus checks the host allowlist before a credential is attached.

Orchestration: leases and fencing

A workflow is a DAG in Redis; workers claim a step with a leased lock

A heartbeat renews the lease; an expired lease is recovered and re-queued

Only the current claim holder can commit a result

Think of a job queue with a visibility timeout, plus a fencing token. No permanent coordinator: any eligible peer can claim a ready step.

Setup19 / 29

The configuration that matters

Stable identity
kind: StatefulSet
spec:
  serviceName: agents-headless
  podManagementPolicy: OrderedReady
  # ordinal 0 is the seed
  containers:
  - env:
    - name: SWIM_BIND_HOST
      valueFrom: {fieldRef:
        {fieldPath: status.podIP}}
      # not 0.0.0.0

Peers find each other by name, and the seed pod starts first.

Slow to shrink
kind: HorizontalPodAutoscaler
spec:
  minReplicas: 3
  maxReplicas: 10
  behavior:
    scaleDown:
      stabilizationWindowSeconds: 300
      policies: [{type: Pods,
        value: 1, periodSeconds: 120}]
  # VPA: InPlaceOrRecreate

Every pod that leaves costs the mesh time to reconverge.

Both protocols
kind: NetworkPolicy
  # mesh ports, ingress + egress
  - ports:
    - {protocol: UDP, port: 8001}
      # steady-state gossip
    - {protocol: TCP, port: 8001}
      # joins and full sync

Joins use TCP; steady-state gossip uses UDP. Allow both.

Running it21 / 29

Observability and cost control

What we watch

  • Workflow and step state, from the ledger
  • Lease expiries and reclaimed steps
  • Pod memory near its limit; OOMKilled
  • Mesh membership, not just readiness
  • Tokens and cost per workflow
  • Provider errors and rate limits

Who provides it

  • JarvisCore: ledger stream, scrubbed traces, per-workflow budgets, optional metrics endpoint
  • Operator: alert rules, dashboards, membership checks
  • Stack: Prometheus and Grafana for metrics, Loki for logs

JarvisCore gives you the events. You build the alerts.
